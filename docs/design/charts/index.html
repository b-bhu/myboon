BoonChart

A small charting library for phones, written from scratch on canvas — no D3, no Chart.js, no build step. Two files: boonchart.js and this page. It covers the five chart jobs a beginner actually has, and nothing beyond them.

SOL
Hold anywhere on the chart to read a point

Line · "which way is it going"

The default. One series, one glance.

  • Colour says the answer. Green if it ended above where it started, red if below. You get the verdict before reading a single number.
  • The number lives above the plot, in a fixed row, not in a floating bubble. Nothing shifts when you scrub, so your thumb never chases it.
  • Y labels sit on the right. Your thumb covers the left side of a phone screen when you scrub.
  • Two x labels only — first and last. On a 360px screen anything more collides.
  • One dot marks "now" at the end of the line.
  • Curves never overshoot. Smoothing uses midpoint beziers, so the line can't bulge past a value that isn't in your data.
BoonChart.line(el, { data: [12.4, 13.1, …], // or [{x:'9AM', y:12.4}] prefix: '$', label: 'LAST 24H', colorByTrend: true, // green up / red down smooth: true, yTicks: 3, height: 180 })

Area · "how much do I have"

Same engine as the line, with a fade under it.

  • Use it for totals — a balance, a count, anything where the space under the line means something. Use the plain line for a price.
  • The fade is the trend colour at 35% dropping to zero. It never introduces a new colour.
  • The readout shows percent change from the first point by default, which is the thing people actually want from a balance chart.
BoonChart.area(el, { data, prefix: '$', zeroBased: true })
Why no candlesticks. A candle encodes four numbers in one mark plus a colour convention you have to be taught. A beginner reading a candle chart is reading the shape of the line and ignoring the wicks. So we ship the line.

Bars · "compare these buckets"

Discrete things side by side. Two modes.

  • Always starts at zero. A bar's length is its value — truncating the axis makes bars lie, so the option doesn't exist.
  • Tap dims the others. The bar you touched stays full strength, the rest drop to 35%. Clearer than a tooltip and it needs no extra chrome.
  • Signed mode (second chart) draws a zero line, colours negatives red, and keeps the axis symmetric so a −$20 bar looks exactly as big as a +$20 one.
  • Labels thin themselves out. Too many for the width and it shows every 2nd, 3rd, nth — always keeping the last. Never rotated text.
  • Bars cap at 28px wide so three bars don't become three billboards.
BoonChart.bars(el, { data: [{label:'W1', value: 240}, …], prefix: '$', label: 'TOTAL' }) BoonChart.bars(el, { data, signed: true }) // ± with zero line

Donut · "what is this made of"

Composition only. Five slices, hard limit.

  • Five slices maximum. Anything past the fifth is summed into a grey "Other". Beyond five, nobody can match a colour to a label on a phone — so the library won't let you.
  • Slices sort largest first, starting at 12 o'clock. Reading order is always the same.
  • Legend is a list, not a scatter. Rows under the chart: swatch, name, percent. Tapping a slice highlights its row and vice versa.
  • The hole holds the total. Tap a slice and the centre becomes that slice's percent — the hole does the work a tooltip would.
  • No pie, only donut. The hole is where the headline number goes, and it makes the arcs easier to compare than wedges meeting at a point.
BoonChart.donut(el, { slices: [{label:'SOL', value: 4200}, …], centerLabel: 'TOTAL', centerValue: '$8.4K', maxSlices: 5 // rest folds into "Other" })

Sparkline · "shape, in a list row"

28px tall. No axes, no labels, no touch.

  • It is not a small chart, it's a word. It says "up and choppy" or "down steadily" at a glance and nothing more. Give it axes and it becomes an unreadable chart.
  • Not interactive on purpose. The row is the tap target — touching the sparkline should open the full chart, not scrub it.
  • Trend colour only. Same green/red rule as the line, so a list reads top to bottom without thinking.
BoonChart.sparkline(el, { data: […], height: 28 })

Progress · "one number against a goal"

The most-read chart in any app, and it isn't canvas.

  • Plain DOM, not canvas. A single bar with a width — it animates for free, scales with text size, and reads correctly to a screen reader.
  • Gold by default per the accent rule: a small, meaningful fill, not decoration.
  • Label left, value right, mono. Either a percent or "value / max" — your call per bar.
BoonChart.progress(el, { value: 68, max: 100, label: 'MONTHLY TARGET' }) BoonChart.progress(el, { value: 1.4, max: 5, prefix:'$', showPct: false }) // renders "$1.4 / $5"

What it won't do

The list matters as much as the features.

  • Zoom and pan: on a phone they fight the page scroll and strand people at a zoom level they can't undo. Give a time-range segmented control instead — that's what the 1D/1W/1M/1Y row is for.
  • Floating tooltips: a thumb covers them. Readout row above the plot, always.
  • Dual axes and stacking: both require the reader to be taught how to read them. Two charts beat one clever chart.
  • Draw-on animation: it delays the answer by half a second, every single time the screen opens.
  • Chart-type switcher: if the data has a right chart, pick it in code. Don't make the reader choose.
Whole library: one file, ~600 lines with comments, zero dependencies. Six chart types. Touch model: finger down snaps to the nearest point and reports it; lift resets. That's the only gesture, across every chart. Vertical page scroll always wins, so a chart never traps the scroll.
